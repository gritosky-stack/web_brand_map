# Заплатки к схеме

Каждая правка базы — **отдельным файлом** здесь, и выполняется только он.

Почему не прогонять `schema.sql` целиком на живой базе: SQL Editor
выполняет файл одной транзакцией, и пока она открыта, затронутые таблицы
стоят под локом. Однажды это вышло дорого — `drop trigger … on auth.users`
держал ACCESS EXCLUSIVE на таблице пользователей до конца прогона, GoTrue не
смог обновить токены, и двоих вошедших разлогинило (2026-09-21). Сам лок
убран, но правило осталось: **живую базу трогаем минимально**.

Порядок работы:

1. новая правка → `patches/NNNN-короткое-имя.sql`, только нужные инструкции;
2. выполнить этот файл в SQL Editor;
3. те же изменения дописать в `schema.sql` — он остаётся полным описанием
   того, что должно быть в базе, и нужен для чистой установки.

Правила для самих заплаток:

- идемпотентность: `if not exists`, `drop policy if exists`, `on conflict`;
- `auth.users`, `auth.sessions`, `auth.refresh_tokens` не трогать вовсе;
  если без триггера на `auth.users` не обойтись — заводить его условно,
  как в `schema.sql`, чтобы повторный прогон не брал лок;
- колонку, которую читает функция на `language sql`, добавлять **до** самой
  функции: её тело Postgres проверяет при создании.
